# Форк для робота-питомца: что изменено

[English](PET.md)

Форк [kaiaai/firmware](https://github.com/kaiaai/firmware) для небольшого домашнего робота: ESP32 DevKit (30 выводов), драйвер L298N, два мотора JGA25-370B с энкодерами, лидар LD19, батарея 4S. «Ум» робота работает на домашнем компьютере — это отдельный проект.

**Состояние: собирается, логика проверена на компьютере, на железе ещё не проверено.** Моторы в пути. Пороги — начальные значения.

## Зачем

Исходная прошивка останавливает моторы только при пропаже Wi-Fi. Три случая оставались без защиты:

| Случай | Как было | Как стало |
|---|---|---|
| Компьютер завис, Wi-Fi работает | Робот едет с последней заданной скоростью | Нет команд `/cmd_vel` 0,5 с — моторы стоп |
| Робот упёрся в препятствие | Регулятор поднимает мощность до предела, мотор и драйвер греются | Мотор под напряжением, а колесо 1 с не крутится — стоп, 2 с команды не принимаются. Так же ловится перепутанный энкодер |
| Батарея села | Напряжение только передаётся в телеметрии | Три ступени: сообщить, затем выключить моторы и лидар, затем глубокий сон с проверкой раз в минуту |

События упора и батареи уходят в тему `/rosout` предупреждениями `SAFETY: ...`, чтобы программа на компьютере могла на них реагировать.

Ещё исправлена одна ошибка исходного кода: в режиме `IN1_IN2` жёсткий тормоз писал в вывод, который оставался привязан к каналу ШИМ, и мотор мог остаться на последней мощности. См. `brakeMotor()` в `motors.h`.

## Настройки

Всё в `kaiaai-esp32/data/config.yaml`, раздел `safety`. Значение `0` отключает проверку. Защита батареи выключена, пока не заданы пороги, поэтому исходные конфиги работают как раньше.

```yaml
safety:
  cmd_vel:
    timeout: 0.5
  stall:
    timeout: 1.0
    rpm_min: 3.0
    pwm_min: 0.15
    hold: 2.0
  battery:
    low: 14.0
    stop: 13.2
    sleep: 12.8
    hysteresis: 0.5
    delay: 3.0
    wake: 60
```

Вверх по ступеням батарея возвращается только при пороге плюс `hysteresis`, а новый уровень должен продержаться `delay` секунд — иначе просадка напряжения под нагрузкой моторов переключала бы его туда-сюда. Если измеренное напряжение ниже половины порога `sleep`, прошивка считает, что батареи нет (питание от USB на столе), и защиту батареи не включает.

Особенность разбора конфига: комментарии допустимы только с начала строки, после значения писать нельзя.

## Сборка

Прошивке нужно ядро Arduino 2.0.x (ESP-IDF 4.4); ядро 3.x не поддерживается. В репозитории есть проект PlatformIO:

```
pio run              # сборка
pio run -t upload    # прошить
pio run -t uploadfs  # залить kaiaai-esp32/data (config.yaml, веб-страница)
```

В Windows держите проект в пути без кириллицы, иначе сборка ESP32 не идёт.

## Тест на компьютере

`test_host/run_test.ps1` собирает `safety.h` с небольшими заглушками вместо частей Arduino и ROS и прогоняет сценарии: пропали команды, упор, заблокировано одно колесо, перепутан энкодер, ступени батареи с гистерезисом, включение на севшей батарее, переполнение 32-битного счётчика микросекунд. Нужен компилятор `zig` (`pip install ziglang`).

## Осталось сделать на железе

- Подогнать делитель батареи по мультиметру (`adc.battery.attenuation`).
- Измерить число импульсов энкодера на оборот и колею.
- Подобрать `stall.pwm_min` под эти моторы.
- На поднятых колёсах убедиться, что срабатывают все три защиты.
